# Interactive workouts

The app and extension target iOS 26. `Shared/WorkoutActionIntent.swift` conforms to `LiveActivityIntent`, which iOS executes in the containing app process without bringing up the app UI. The extension compiles the intent's parameters and UI; the `SPOTTER_WIDGET` condition omits the app-only handler there.

`WorkoutRuntime` coalesces foreground and background launches into one asynchronous database load and one `TrainingStore`. No App Group is needed because the extension never opens the database. Existing SQLite data remains at its original URL. V5 adds an optional `sessionData` attribute using inferred lightweight migration; old model versions remain bundled.

Completed performance lives only in the existing exercise/set entities. The workout's session data contains the selected exercise/set, pending weight/reps, absolute rest deadline, and revision. Legacy selection/rest preferences migrate once. Saving a command updates completed sets and the session revision in one main-actor Core Data transaction. Buttons carry the rendered revision: duplicate delivery or a stale rendered button becomes a no-op and refreshes the activity. Failed saves roll back. Complete on a selected recorded set edits that set; complete on the pending set inserts one record. Undo reopens the most recent recorded set across the workout by removing it and restoring its input values.

Foreground changes and intents both use this store. Snapshot content contains only display values and a revision. Intent execution checks activity availability, the preference, and the workout's active status. Finish/discard and preference changes end activities. Dismissed activities are not restarted. Rest uses an absolute deadline and system-rendered countdown, so suspending the app does not suspend the timer. The ActivityKit stale date is the rest deadline. When iOS refreshes the layout, the expired rest deadline restores Log Set. iOS can defer that layout refresh while the app sleeps: the system countdown still reaches zero, and End Rest provides an explicit return to logging. It never logs a set as a side effect. No background timer or polling is used.

Lock Screen and expanded Dynamic Island show one primary action: Log Set while ready, End Rest while resting, or a link to continue/review when the planned sets are complete. A 44-point Undo control corrects the last logged set. Tapping the exercise or load opens the saved session for editing. Compact/minimal Island presentations show status and link into the app. Advanced text entry, finishing a workout, and destructive workout deletion remain in the app. iOS controls authentication, activity lifetime, and background launch availability (including after force-quit or before first unlock). No server or push service is used.

Apple references:
- https://developer.apple.com/documentation/appintents/liveactivityintent
- https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities

## Verification notes

The simulator integration tests log, undo, and skip rest on the actual system card, then check the same recorded sets and load in Spotter. A separate test lets the countdown expire while Spotter stays backgrounded and checks that End Rest returns to logging without changing recorded set count. iOS 26's AppEnum resolver cancelled the initial enum-based payload; the production intent transports a validated string action code instead. The 160-point system-card height is respected by a two-line summary and one row of 44-point controls; there are no weight/reps steppers or navigation toolbars. The test also handles first-use permission prompts and the simulator's widget accessibility tap-point issue. These test accommodations do not alter production behavior.

Final October 10 run: both system-card interaction tests passed on the dedicated iPhone 17 Pro / iOS 26 simulator. Inspected the ready card, steady rest-at-zero card, compact Island, and expanded Island. The Lock Screen uses its own dark environment even when the app is light; the background is resolved to that same environment before passing it to SpringBoard, avoiding white lettering on a white card. The expanded exercise title and set count fit without clipping. Minimal Island has a separate symbol-only preview; a real two-activity minimal presentation and physical-device VoiceOver/lifecycle behavior remain unverified. Some captured transitions include the system's crossfade between layouts; the steady-state captures are clear.
